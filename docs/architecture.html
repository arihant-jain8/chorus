Chorus · architecture

Chorus Architecture Map

Every struct, its fields, and its methods across the five layers of the multi-output audio router. Each card folds open for detail. Three flows run through it: audio down to your devices, control from the UI into the engine, and events back from the engine to the UI.

Audio path — samples flowing to your devices Control path — UI requests flowing to the engine Event path — engine announcements back to the UI

Source of truth is the code; this page mirrors it. Each card carries its file:line — update the matching card in the same commit that changes a struct.

The three flows at a glance

Audio — one capture → many devices

  1. system audio plays
  2. default output device
  3. CaptureSource WASAPI loopback
  4. push into N ring buffers the fan-out
  5. OutputSink × N pop + ×volume / mute
  6. sink devices play

Control — UI request → engine

  1. drag a slider / click mute
  2. invoke("set_…") JS → Rust
  3. #[tauri::command] fn
  4. Chorus.set_… → tx.send(Command)
  5. audio thread loop
  6. Router → sink atomic

Events — engine announces → UI repaints

  1. default device changes (re-tap)
  2. event_tx.send(Event::DevicesChanged) plain Rust channel
  3. bridge thread: for ev in event_rx
  4. handle.emit("state-changed", state()) Rust → JS
  5. listen("state-changed", …)
  6. renderState(payload) repaints

Ring buffer (ringbuf, SPSC): HeapRb::<f32>::new(capacity).split() → (HeapProd, HeapCons). The producer lives in the capture callback, the consumer in the output callback — a lock-free pipe between two unsynced clocks. Capacity ≈ 100 ms.

↕ cpal streams talk to the OS
5OS / hardware

Windows · WASAPI · cpal 0.18 · volumecontrol

WASAPI loopback

capture

Captures whatever is playing on the default output device — this is how Chorus "hears" system audio with no microphone.

cpal 0.18 auto-enables loopback when build_input_stream is called on a render (output) device.

Sink devices

playback

Each OutputSink drives one render endpoint — speakers, headphones, HDMI.

Independent clocks; the ring buffer absorbs the drift between capture and each sink.

volumecontrol

endpoint volume

AudioDevice::from_default() / from_name() — moves the real Windows slider for the source (out-of-path, can fail).

Also used to max each sink's OS endpoint at startup, so our software gain is the only sink attenuator.
